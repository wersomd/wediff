# Telegram-напоминания

Сводка WH·OS включает открытые задачи на сегодня и просроченные, сроки активных
проектов, долги в обе стороны и активные подписки. Даты считаются по Алматы.
Закрытые задачи и проекты, погашенные долги и выключенные подписки исключаются.
Остаток долга вычисляется после всех частичных погашений без округления float.

## Подключение сервера

1. Применить миграцию `20261008050000_reminder_delivery` командой
   `npx prisma migrate deploy` на целевом сервере после проверки БД.
2. Задать серверные переменные `TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_ID`,
   `CRON_SECRET` (случайная секретная строка), `APP_BASE_URL` (публичный адрес
   приложения, например `https://your-app.example.com`). Значения не передаются
   в браузер. Бот должен иметь возможность отправлять сообщения в выбранный чат.
3. Развернуть приложение. В `vercel.json` задан cron `0 4 * * *` — ежедневно
   около 09:00 по Алматы. Для другого хостинга настроить ежедневный GET
   `/api/cron/reminders` с заголовком `Authorization: Bearer <CRON_SECRET>`.
4. В настройках приложения выбрать категории. При первом подключении включены
   все категории. Изменение настроек отменяет старые неотправленные части;
   новый набор категорий применяется к следующей дневной сводке.
5. Проверить авторизованный вызов маршрута и фактическое получение сообщения.
   Пустая сводка ничего не отправляет. Наличие переменных само по себе не
   подтверждает активность расписания; подтверждение — запись доставки и чат.

## Надёжность и ограничения

- Снимок дневной сводки фиксируется в БД с блокировкой PostgreSQL и уникальным
  ключом `(day, part)`. Параллельные вызовы не отправляют одну часть одновременно.
- Длинная сводка разбивается на сообщения до 3500 UTF-16 единиц. Данные выводятся
  простым текстом без интерпретации HTML/Markdown. Заголовки сокращаются, ссылки
  на исходные записи сохраняются.
- На запрос Telegram отведено 15 секунд. За один вызов worker берёт новые части
  не дольше 35 секунд, оставляя время для завершения текущего запроса.
- HTTP-код сам по себе не доказывает успех: проверяется Telegram `ok` и message_id.
- Известные ошибки имеют максимум 3 попытки и паузу не меньше 60 секунд либо
  Telegram retry_after. Ежедневный cron не обеспечивает повтор внутри того же
  дня: после устранения ошибки авторизованно вызовите маршрут повторно.
- Неопределённый результат (таймаут, невалидный ответ, прерванный worker) получает
  `unknown` и не повторяется автоматически: Telegram мог уже принять сообщение.
  Проверьте чат. На следующий день актуальные обязательства войдут в новую сводку.
- Маршрут возвращает 503, если есть ошибки или незавершённые части; 401 при
  неправильном секрете. В ответе нет текста задач и секретов.
- Неотправленные части вчерашней сводки не догоняют пользователя на следующий
  день: новый день получает свежую сводку. Журнал и тексты удаляются через 30 дней
  при следующем успешном запуске worker.
- После изменения сроков или погашения долга обновляется следующая дневная сводка.
  Повтор уже сформированной сводки в тот же день использует сохранённый снимок.
- Включён RLS; доступ идёт только через серверное подключение Prisma с подходящими
  правами. Клиентский доступ к журналу не предусмотрен.

## Проверки

`npm test` покрывает отбор записей, границы дат, частичные погашения, разбиение
сообщений, ошибки транспорта, параллельные claims, ограничения попыток и
авторизацию маршрута. Для активации в production дополнительно необходимы
применённая миграция, настроенный планировщик и подтверждённая доставка в чат.
